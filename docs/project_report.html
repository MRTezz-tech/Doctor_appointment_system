1. Project Abstract & Introduction

1.1 Abstract

In conventional outpatient medical centers, scheduling appointments is frequently conducted via manual paper logs or basic telephone requests. These legacy methods suffer from long patient waiting queues, human booking errors, lack of visibility into doctor shift availability, and inadvertent double-booking of time slots.

DocCare is an enterprise-grade clinical management web application engineered using Core PHP, MySQL, Bootstrap 5, and JavaScript. The application features comprehensive Role-Based Access Control (RBAC) separating three operational roles: Patients, Doctors, and Admin/Receptionists. A real-time asynchronous JavaScript (AJAX) slot calculation engine queries active bookings and suppresses already occupied or elapsed times. Concurrency-safe atomic database validation eliminates double-booking risks.

1.2 Problem Statement

  • Physical Queue Congestion: Patients are compelled to visit clinics in person without advance notice of real-time slot occupancy.
  • Double-Booking Vulnerability: Multiple receptionists or parallel patient submissions often assign the same doctor to two different patients at identical times.
  • Lack of Real-Time Lifecycle Tracking: Patients remain unaware whether their booking is Pending, Confirmed, Completed, or Cancelled.
  • Disorganized Practice Administration: Doctors lack centralized oversight over their patient history, daily schedules, and consultation fees.

1.3 Objectives of Proposed System

  • To deliver a zero-dependency, professional web portal operating seamlessly on standard XAMPP stacks.
  • To automate consultation slot generation according to individual doctor shift timings (start/end times, working days, and slot duration intervals).
  • To enforce strict data integrity through PDO prepared statements, input sanitization, and Bcrypt password hashing.
  • To provide an intuitive, responsive medical blue-and-white theme accessible across mobile, tablet, and desktop viewports.

5. Core Algorithms & Business Logic

5.1 Real-Time Slot Calculation Logic

When a patient selects a doctor and a consultation date, the frontend triggers an asynchronous fetch() request to api/get-slots.php. The backend calculates time intervals dynamically: 

1. Verify doctor status is 'active'.
2. Verify selected_date >= CURRENT_DATE() (Strict past-date rejection).
3. Compute day_of_week = DATE_FORMAT(selected_date, '%W') (e.g., 'Monday').
4. Check if day_of_week exists in doctor.available_days list.
   - If not present: Return message "Doctor is not available on [day]".
5. Query existing active bookings:
   SELECT appointment_time FROM appointments 
   WHERE doctor_id = :id AND appointment_date = :date AND status IN ('Pending', 'Confirmed');
6. Iterate time from doctor.start_time to doctor.end_time stepping by (doctor.slot_duration * 60 seconds):
   - IF (date == CURRENT_DATE() AND slot_time <= CURRENT_TIME()):
       mark slot as passed (disabled).
   - ELSE IF (slot_time in booked_slots):
       mark slot as booked (disabled).
   - ELSE:
       mark slot as available (selectable radio button).
7. Return JSON response to client DOM for rendering.

5.2 Concurrency & Double-Booking Prevention

Even if two users view the booking page simultaneously, the system prevents race conditions at the database transaction level through the validate_slot_availability() function: 

// Server-Side Pre-Insert Query
$sql = "SELECT id, status FROM appointments 
        WHERE doctor_id = ? 
          AND appointment_date = ? 
          AND appointment_time = ? 
          AND status IN ('Pending', 'Confirmed')";
// If row count > 0: Reject transaction with 'Slot Already Booked' error.

6. Security Implementation

1. Bcrypt Password Hashing
Passwords are never stored in plaintext. Passwords are encrypted using PHP's native password_hash($pass, PASSWORD_DEFAULT), generating a secure salted Bcrypt hash ($2y$ format). Verification is performed via password_verify().
2. CSRF (Cross-Site Request Forgery) Token Defense
Every form contains an anti-CSRF token generated using cryptographically strong pseudo-random bytes: $_SESSION['csrf_token'] = bin2hex(random_bytes(32)); Submissions are verified using timing-attack-safe comparison: hash_equals($_SESSION['csrf_token'], $_POST['csrf_token']).
3. SQL Injection Neutralization
100% of database interactions are executed using PHP Data Objects (PDO) with prepared statements. Parameter binding isolates SQL instructions from user inputs.
4. XSS (Cross-Site Scripting) Defense
All user-generated values rendered in HTML pages are wrapped in the global escaping function: function e($str) { return htmlspecialchars((string)$str, ENT_QUOTES, 'UTF-8'); }.

9. Conclusion & Future Scope

9.1 Conclusion

The DocCare Doctor Appointment System successfully demonstrates a complete, reliable, and secure web application for modern medical clinic operations. Built strictly with standard web technologies (Core PHP, MySQL, Bootstrap 5, and JavaScript), it requires no third-party framework overhead, making it lightweight and easy to deploy on local XAMPP environments. The automated slot generation, role-based security, and double-booking prevention resolve core challenges encountered in outpatient healthcare management.

9.2 Future Scope

  • Payment Gateway Integration: Online payment of consultation fees using UPI, Debit/Credit cards via Razorpay or Stripe.
  • Automated Notifications: Instant SMS notifications (Twilio) and Email booking confirmations (PHPMailer).
  • Telemedicine Video Consultations: WebRTC-powered remote video consultations between doctors and patients.
  • E-Prescriptions: Enabling physicians to generate and attach digital medical prescriptions to completed appointments.
